
## What is **ioredis**

**ioredis** is a **Node.js client library for Redis** that provides a powerful and feature-rich way to connect your Node.js applications to **Redis**, an in-memory data store used for caching, queues, pub/sub, and session storage.

It is widely used in **high-performance Node.js applications**.

### Example (basic usage)

```javascript
const Redis = require("ioredis");
const redis = new Redis();

await redis.set("name", "John");
const value = await redis.get("name");

console.log(value); // John
```

---

# Difference: ioredis vs node-redis

The official Redis client for Node.js is **node-redis**.

| Feature                  | ioredis           | node-redis          |
| ------------------------ | ----------------- | ------------------- |
| Maintainer               | Community         | Official Redis team |
| Performance              | Very good         | Very good           |
| Redis Cluster support    | Built-in & stable | Added later         |
| Sentinel support         | Strong            | Supported           |
| Auto reconnection        | Advanced          | Basic               |
| Offline queue            | Yes               | Limited             |
| API style                | Promise-based     | Promise-based       |
| Popularity in production | Very popular      | Growing             |

---

# Key Advantages of ioredis

### 1️⃣ Better Cluster Support

If you're using **Redis Cluster**, **ioredis handles it very smoothly**.

```javascript
const Redis = require("ioredis");

const cluster = new Redis.Cluster([
  { host: "127.0.0.1", port: 7000 },
  { host: "127.0.0.1", port: 7001 }
]);
```

---

### 2️⃣ Built-in Auto Reconnection

If Redis disconnects, **ioredis automatically reconnects** without crashing your app.

---

### 3️⃣ Offline Queue

Commands sent while Redis is reconnecting are **queued and executed later**.

---

### 4️⃣ Pub/Sub & Streams Support

Great support for:

* Pub/Sub
* Pipelines
* Transactions
* Streams

---

# When to Use Which

### Use **ioredis** when:

✔ You use **Redis Cluster**
✔ You want **robust reconnection handling**
✔ You need **high reliability**

### Use **node-redis** when:

✔ You want the **official Redis client**
✔ Simple caching use cases
✔ Minimal dependencies

---

# Real-world Example

Many frameworks and tools use **ioredis**, for example:
